# 책봄 공유 시나리오

> 다른 선생님이 이 저장소를 받아 **자기 Firebase·자기 Vercel**로 나만의 책봄을 띄우는 안내입니다.
> 조사 기준: imuzikr/class-book-worksheets, main (PR #72 병합 이후).

## 0. 저장소에서 확인한 사실 요약

## 2. 받는 사람 시나리오: "옆 학교 국어 선생님 김봄 선생님"

> 김봄 선생님은 코딩을 해 본 적이 없습니다. AI 코딩 도구를 쓸 줄 압니다.
> 목표는 **자기 반 학생들이 쓰는 '나만의 책봄'**입니다.
> 원칙: 원작자 Firebase를 빌려 쓰지 않습니다. **자기 Firebase와 자기 Vercel**을 씁니다.

### 2-1. 준비물 (30분)
- 구글 계정 1개(Firebase·관리자 로그인용)
- GitHub 계정, Vercel 계정(GitHub로 가입)
- 컴퓨터에 Node.js 22, Git, AI 코딩 도구
- (선택) 규칙 시험용 Java 21. 없으면 `npm run deploy -- --skip-tests`로 건너뛸 수 있지만 권하지 않습니다
- (선택) Storage(그림 첨부)를 쓰려면 Blaze 요금제가 필요할 수 있습니다

### 2-2. 저장소 가져오기
1. github.com/imuzikr/class-book-worksheets 에서 **Fork**합니다(템플릿이 켜져 있으면 "Use this template"도 됩니다).
2. 클론 후 `npm install`, `npm run dev`.
3. 환경변수를 넣기 전이면 원작자 Firebase 기본값으로 붙을 수 있습니다. **화면만 보려면** apiKey를 `YOUR_API_KEY`로 두어 **데모 모드**로 봅니다.

### 2-3. Firebase 프로젝트 만들기
1. console.firebase.google.com 에서 새 프로젝트(예: `bom-kim-books`). Analytics는 꺼도 됩니다.
2. 웹 앱을 등록하고 `apiKey`, `messagingSenderId`, `appId`, 프로젝트 ID를 메모합니다.
3. **Authentication** → Google만 사용 설정.
4. **Firestore** 생성(서울 `asia-northeast3` 권장. 위치는 나중에 못 바꿉니다).
5. (그림 첨부) **Storage** 시작.
6. Authentication → 승인된 도메인에 나중에 생길 Vercel 주소를 추가합니다. `localhost`는 기본으로 있습니다.

### 2-4. 내 Firebase 값 넣기
1. `cp .env.example .env.local` 후 값을 채웁니다(`.env.local`은 Git에 올리지 않습니다).
   - `NEXT_PUBLIC_FIREBASE_API_KEY`
   - `NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN` (보통 `<projectId>.firebaseapp.com`)
   - `NEXT_PUBLIC_FIREBASE_PROJECT_ID`
   - `NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET` (보통 `<projectId>.appspot.com` 또는 `.firebasestorage.app`)
   - `NEXT_PUBLIC_FIREBASE_MESSAGING_SENDER_ID`
   - `NEXT_PUBLIC_FIREBASE_APP_ID`
2. `.firebaserc`는 환경변수를 못 쓰므로 `firebase use --add`로 자기 프로젝트를 고릅니다.
3. Vercel Project Settings → Environment Variables에도 같은 이름을 넣습니다.
4. (선택) 서버 키 `FIREBASE_ADMIN_*`, `NAVER_*`는 Vercel에만 넣습니다. **절대 GitHub에 올리지 마세요.**

### 2-5. 보안 규칙 배포 (Vercel과 따로!)
```bash
npx firebase-tools login
npm run deploy
```
- Storage 규칙을 처음 올릴 때 "Firestore 접근 권한"을 물으면 **Y**. 거부하면 그림이 전부 막힙니다.
- 규칙을 바꾸면 이 단계를 **다시** 합니다. GitHub·Vercel 배포로는 규칙이 바뀌지 않습니다.

### 2-6. Vercel 배포
1. vercel.com → Add New → Project → 내 Fork Import. Next.js는 자동 인식됩니다.
2. 환경변수를 넣고 Deploy.
3. 나온 주소를 **2-3의 6번(승인된 도메인)**에 넣었는지 확인합니다.
4. 이후 main push 시 자동 재배포됩니다.

### 2-7. 교사 가입 코드
1. Firebase 콘솔 → Firestore → 컬렉션 `config` → 문서 ID `teacherSignup`
2. 필드 `code`(유형 **string**), 값 **4자 이상**(예: `bom2026`)
3. 앱에서 구글 로그인 후 가입 화면(또는 '선생님이세요?')에 이 코드를 넣으면 선생님이 됩니다.

### 2-8. 관리자 지정
1. 앱에 구글로 한 번 로그인합니다(`users/{uid}`가 생깁니다).
2. 콘솔 → `users`에서 내 문서의 `role`을 `admin`으로 바꿉니다.
3. 새로고침하면 반영됩니다. 이후 역할은 앱 안 역할 관리에서 바꿀 수 있습니다.

### 2-9. 첫 반 만들고 확인
1. 선생님으로 `/books`에서 **＋ 반 만들기**(먼저 체험용 샘플 반으로 익혀도 됩니다).
2. 반 **참여 코드** 확인.
3. 다른 브라우저(시크릿)에서 다른 구글 계정으로 참여.
4. 활동 하나를 만들고 글·그림을 저장해 봅니다.

### 2-10. 업데이트 받는 법
- Fork면 GitHub에서 **Sync fork → Update branch**. Vercel이 자동 재배포합니다.
- 환경변수로 연결했으므로 Firebase 값 충돌은 거의 없습니다. `.firebaserc`만 자기 프로젝트인지 확인하세요.
- `firestore.rules`, `storage.rules`, `firestore.indexes.json`이 바뀌면 `npm run deploy`를 **다시** 합니다.
- "Use this template"로 만들었다면 자동 동기화가 없습니다.

## 3. 자주 막히는 곳

| 증상 | 원인과 해결 |
|---|---|
| `auth/unauthorized-domain` | Vercel 주소가 Firebase 승인된 도메인에 없음 → 2-3의 6번 |
| 로그인은 되는데 데이터가 이상하거나 원작자 반이 보임 | 환경변수가 비어 원작자 기본값을 씀 → 2-4 |
| 가입 코드를 넣어도 선생님이 안 됨 | `config/teacherSignup` 없음·문자열 아님·4자 미만, 또는 규칙 미배포(2-5) |
| "권한 없음" | 규칙 미배포 → `npm run deploy` |
| 그림만 안 보임 | Storage 미시작(Blaze 가능) 또는 첫 배포 때 Firestore 접근 거부 |
| `npm run deploy` 규칙 시험 실패 | Java 21 설치 또는 `--skip-tests` |
| '체험반 15명'만 나옴 | apiKey가 `YOUR_...`(데모)이거나 샘플 반에 들어 있음 |
| 색인 오류 | `npm run deploy -- --indexes-only` 후 대기 |
| 학교 와이파이에서 구글 로그인 막힘 | `lib/firebase.js`의 로그인 프록시(`PROXIED_AUTH_HOSTS`) — 고급 |
| 관리자 메뉴 안 보임 | `role`이 정확히 `admin`인지 확인 후 새로고침 |

## 4. 단계별 AI 프롬프트 예시

- **준비**: "내 컴퓨터에 Node.js 22, Git, Java 21이 있는지 확인하고, 없으면 설치 방법을 하나씩 알려 줘."
- **가져오기**: "내 GitHub 저장소 `<내아이디>/class-book-worksheets`를 이 폴더에 클론하고 `npm install` 후 `npm run dev`로 띄워 줘. 화면만 보려면 `.env.local`의 apiKey를 `YOUR_API_KEY`로 두어 데모 모드로 보여 줘."
- **내 Firebase 연결**: "`.env.example`을 보고 `.env.local`을 만들어 줘. 프로젝트 ID는 `<ID>`, apiKey는 `<값>`, messagingSenderId는 `<값>`, appId는 `<값>`이야. `.firebaserc`는 `firebase use --add`로 내 프로젝트를 고르게 도와 줘."
- **규칙 배포**: "`npx firebase-tools login`과 `npm run deploy`를 도와 줘. Firestore 접근 권한 질문에는 Y. 오류는 쉬운 말로."
- **Vercel**: "이 저장소를 Vercel에 처음 배포하는 화면 순서와, 배포 주소를 Firebase 승인된 도메인에 넣는 방법을 알려 줘. `.env.local`과 같은 `NEXT_PUBLIC_FIREBASE_*`를 Vercel에도 넣어 줘."
- **가입 코드 / 관리자**: "Firestore에 `config/teacherSignup`의 `code` 넣기, `users`에서 내 `role`을 `admin`으로 바꾸는 클릭 순서를 알려 줘."
- **업데이트**: "원본 imuzikr/class-book-worksheets의 최신을 내 Fork에 가져와 줘. 내 환경변수는 지키고, 규칙 파일이 바뀌면 `npm run deploy`도 해 줘."
- **문제 해결**: "책봄에서 `<증상>`이 나와. README와 docs/공유-시나리오.md를 읽고 원인과 고치는 법을 먼저 설명해 줘."
